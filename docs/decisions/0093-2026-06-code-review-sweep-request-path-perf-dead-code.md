# 2026-06 code-review sweep: request-path perf, dead-code removal, prismlib/JS-lib consolidation

A full-codebase review (dead code / simplification / performance) landed as one branch; the non-obvious choices, so they aren't re-litigated: (1) **rpcd replies now prefer `luci.jsonc`'s C encoder** (`json_stringify_reply`) — the pure-Lua fallback ran 5 chained `gsub`s per string over up to 1000 syslog lines on every 2s poll. Caveat that shaped the implementation: luci.jsonc encodes an *empty* Lua table as `[]` where the fallback (and rpcd's exec plugin, which requires a JSON object) expects `{}` — so the `list` reply and any all-empty `call` reply stay on the fallback, and nested empties were audited (every one is a list the JS iterates or indexes; `[]` is the more correct shape). Verify on-target before release. (2) **`migrate_legacy_selectors` is gated by a tmpfs marker** (`/var/etc/prism/.selector-migrated`) — its "one-shot" comment notwithstanding, it ran a UCI load + node foreach on every RPC call. Marker on tmpfs = re-checked once per boot; if the marker can't be written the gate degrades to the old per-call behaviour rather than skipping the migration. (3) **Status page polls on ONE rescheduled timer** — the log tail had its own parallel 2s chain (4 rpcd forks / 2s over two HTTP requests); all four reads now fan into a single `Promise.all` tick, which LuCI batches into one HTTP request. A combined `get_dashboard` RPC (1 fork instead of 4) is the natural follow-up if the poll cost still shows. (4) **`rpcd-mod-rpcsys` dropped from LUCI_DEPENDS** — nothing references the `rc`/`sys` ubus objects it provides, and the ACL only grants `luci.prism` + `uci prism`, so LuCI core paths can't need it either. NEEDS a clean-image install test on real hardware before the next release. (5) **Security whitelists live in prismlib** — `RESERVED_TAGS` and `ALLOWED_PROTOCOLS` were mirrored between `luci.prism` and `build-config` with keep-in-sync comments; one shared table each removes the drift hazard. Same consolidation for the atomic 0600 write (`lib.write_secure`, previously five inline copies), the WAN-DNS probe, the procd `singbox`-instance walk, the nodes-dir listing, and the probe host/config constants. (6) **JS lib modules** `lib/subs.js` (uid→name/order maps + sort), `lib/badges.js` (latency badge), `lib/subsync.js` (Sync button) replace the copies decision #22 ("copy-pasted rather than extracted — one helper isn't worth a new require for a single consumer") and #20 ("inlined … below the threshold for a shared module") deliberately kept — at two-to-three consumers each and with observed drift (the Sync handlers had already diverged on spinner cleanup), the threshold is crossed. (7) **`emit_bypasses` is one awk pass** over `uci show prism` instead of ~4 forks per bypass section; validation regexes are byte-equivalent to the old greps (verified against busybox awk with fixtures, including the values the old code deliberately accepted, e.g. out-of-range IPv4 octets — range checking stays in the JS validator). (8) **basic.js loses the per-subscription failure notification**: it now makes one `list_outbounds` call instead of N× `list_subscription_nodes`, and a failed RPC vs an unsynced subscription both surface as the picker's "No nodes yet" hint — judged acceptable since the old per-sub distinction was already invisible in the common case. (9) The dead `reload` RPC + ACL grant, main.js's unreachable sub-tab machinery, firewall.sh's uncalled `restart`, and nodes.js's `_waitTestDone` (whose timers escaped `_teardown`) were removed outright.

# Release packages published as a signed OpenWrt-style feed on GitHub Pages

Releases were install-only via one-off `wget <release-asset-url>` one-liners — no `apk add`/`opkg install` by name, no in-place `upgrade`, and every new version meant a fresh URL. Added a proper package feed (`pages.yml` → GitHub Pages) so a router adds the repo once and then installs/upgrades Prism through its package manager. `feed.sh` rebuilds the whole feed from **every** `v*` release (not just the newest) so historical versions stay installable and apk/opkg can compute upgrades; it pulls release assets with `gh`, strips release.yml's `-openwrt-XX.YY` platform suffix to recover the canonical `package.sh` filenames (apk mkndx's default name spec and opkg's `Filename:` field both expect those), and emits two indexes for the one `noarch`/`all` package — apk v3 `apk/Packages.adb` via `apk mkndx --sign-key`, and opkg `opkg/Packages(.gz)` with a detached `usign` signature over the *uncompressed* `Packages` (matches OpenWrt buildroot's `usign -S -m Packages`; opkg gunzips `Packages.gz` and verifies against `Packages.sig`). **One index per format covers all architectures** because the package is arch-independent — no per-arch subdirectories, and the apk feed is added as a plain `…/apk/Packages.adb` URL line in `/etc/apk/repositories.d/customfeeds.list` (OpenWrt 25.12's apk config dir, confirmed from the LuCI apk page — **not** Alpine's single `/etc/apk/repositories` file, and **no** `ndx`/`v3` prefix: apk auto-detects the v3 ndx index from the `.adb` suffix, exactly as the stock `distfeeds.list` entries do). **Signed, not unsigned** (user choice): keys are repo secrets `APK_SIGN_KEY` (EC prime256v1 PEM, `openssl ecparam -name prime256v1 -genkey` — the same scheme OpenWrt's own apk build signs with, so the stock 25.12 apk client verifies it; **not** RSA) and `OPKG_SIGN_KEY` (usign ed25519); the public halves live in-repo at `feed/keys/` and are republished in the feed for clients to trust (`/etc/apk/keys/` for apk — v3 matches by key identity so the filename is cosmetic; `opkg-key add` for opkg — stored under `/etc/opkg/keys/<fingerprint>`). `feed-keygen.sh` mints both keypairs once (private keys to git-ignored `.feed-keys/`, never committed); an `install-usign` composite action builds OpenWrt's `usign` from source (dependency-free C, cmake + cc, `USE_LIBUBOX` off) mirroring the existing `install-apk-tools`. **Releases-only** (user choice): the rolling `snapshot` pre-release is excluded from the feed and stays a manual-install URL. Two behaviours are environment-dependent and flagged to verify on real hardware before relying on them (per the "don't ship on assumption" rule): that OpenWrt 25.12's apk resolves a `noarch` package from the feed against the router's own arch (the plain-`.adb`-URL-in-`customfeeds.list` mechanism itself is confirmed from the OpenWrt apk config page), and that a `usign`-signed `Packages.sig` validates under 24.10's opkg. Manual one-time setup the workflow can't do for itself: run `feed-keygen.sh`, add the two secrets, enable Pages (Source = GitHub Actions).

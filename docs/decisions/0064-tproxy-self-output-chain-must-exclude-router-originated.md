# `tproxy_self` output chain must exclude router-originated DNS (port 53)

Capturing the router's own `:53` traffic deadlocks DNS: dnsmasq's upstream forwarding gets TPROXY'd into sing-box (`action: hijack-dns`), but sing-box's resolver detours through the proxy node, and dialing that node needs the node's hostname resolved via the `local-net` server — which is dnsmasq again. The loop means no name ever resolves and all router traffic dies. `build_nft`'s `output` chain now emits `udp dport 53 accept` / `tcp dport 53 accept` before the catch-all `meta mark set`, so the router's own DNS goes direct while everything else it originates is still proxied. LAN-client DNS is unaffected — it is still hijacked by the `prerouting` chain. Literal-IP nodes happened to dodge the loop (no hostname resolution needed); hostname nodes — the common case — hit it, which is why "Proxy router traffic" appeared to block everything.

# Settings page reorganised; two NamedSections share the `global` UCI section (Rule-sets + Logging)

The 2026-05-23 reorg lumped log levels and rule-set fetching into one "General" section because of a constraint stated as "multiple `form.NamedSection`s binding the same UCI section name would collide on the generated DOM id." Re-reading `form.js`'s `NamedSection.renderContents` (form.js ~4271/4274 in current LuCI master): the wrapper `<div class="cbi-section">` gets `id="cbi-<config>-<section_id>"` (only when the UCI section is absent), and the inner `<div class="cbi-section-node">` gets the same id (when present). The *per-option* ids are `cbid.<config>.<section_id>.<optname>` — keyed on the section_id string, not on the JS section object. So two NamedSections both bound to `('global', 'prism')` only duplicate the wrapper-div id (HTML-invalid but functionally inert — no form code keys off it); every per-option cbid stays unique as long as no option name repeats across the two sections, which is what save/load/validate/`getUIElement` actually rely on. The constraint as previously stated was overstated. The Settings page now uses two real sections — `Rule-sets` (delivery + download_detour) and `Logging` (sing-box + Prism log levels) — both binding `global`. The Logging section is wholly Advanced: its wrapper `.cbi-section` gets the `prism-advanced` class in `_postRender` (located by walking up from its first option's input element via `firstOpt.cbid(section.section)` lookup, since `section.children` is the framework's option array), so the section title + every row hide as one unit. This replaces the previous "inject an h3 subheader before log_level" hack and drops the `_prismSubheader`/`prism-subheader` CSS plumbing. Other reorg moves: `tproxy_self` (Proxy router traffic) demoted from Advanced → Standard (no day-to-day reason to disable); `managed_dns` promoted to Advanced (default on, no standard reason to disable); `log_level` + `prism_log_level` + `ruleset_download_detour` moved to Advanced; mode-specific Network rows (tproxy / tproxy_mixed / tun groups) reordered to sit directly under `Mode` so each mode's options are visually adjacent to the selector that reveals them; `Enable IPv6` moved to the bottom of Network as the only mode-independent row. Section order on the page is now Network → DNS → Rule-sets → Logging → Raw overrides, reading top-to-bottom as the traffic flows then ending with operator/diagnostic knobs.

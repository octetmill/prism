# `country` condition kind removed; `country_provider` setting removed

Anyone touching routing rules already understands the rule-set catalog, so the `country=cn` shortcut — which only expanded to `<provider>/geoip-cn` plus `<provider>/geosite-cn` (when the catalog confirmed the geosite existed) — was sugar for a user who already knows what those tokens mean. Removing it deletes one condition kind, the 30-entry `COUNTRIES` autocomplete array, the `countrySuggest` plumbing on `ConditionList`, the `country_provider` dropdown in Rule-set sources, the matching UCI default, the `else  -- country` branch in `build-config:resolve_condition`, the `country_provider` / `catalog_has` keys in `prepare_rules`'s ctx, and `load_catalog()` (its only consumer was the country geosite-availability gate; `rulesets-cache.json` itself stays — `luci.prism`'s `list_rulesets` still reads it for the autocomplete catalog). A country-style match is now expressed as two `ruleset` conditions joined by OR (`sagernet/geoip-cn` OR `sagernet/geosite-cn`) — the same two rule-sets the shortcut emitted, just spelled out. No migration script: existing `kind=country` conditions become no-ops (`compile_condition` falls through to `node = nil`, and a rule whose every condition resolves to nothing is skipped); the user re-adds them as ruleset conditions on upgrade. The legacy `90-prism-migrate-rules` / `91-prism-migrate-conditions` uci-defaults still emit `country` for pre-2026-05-22 schemas, which will likewise become dead rules on a first-time upgrade from one of those very old schemas — acceptable because the audience for that path is empty in practice.

# Latency probes run on an ephemeral sing-box probe instance; `include_all_nodes` and the hidden `_prism_test_all` group are removed; the running config is always lean

Supersedes the include-all part of decision #19. The clash API can only probe outbounds registered in the config that serves it, so making every subscription node testable previously meant emitting all of them into the *production* config (`include_all_nodes=1`, ~175 KB JSON + ~600 KB Go state for 300 nodes, plus an unreadable config preview and a `/proxies` list dominated by test-only freight). New architecture: `build-config --probe` emits a minimal second config — every concrete node Prism knows about (manual + every subscription, same loaders/sanitisers as production via the factored `load_all_nodes`), a loopback clash API on **127.0.0.1:9091**, the shared `local` DNS server (factored `build_local_dns_entry`), and nothing else: no inbounds, no route rules, no rule-sets, and critically no `cache_file` (the live instance holds a bbolt lock on cache.db). `test-all-runner` builds it, forks `sing-box run` directly (NOT via procd — the probe instance is runner-owned and ephemeral; the "always go through procd" rule applies to the production service), waits for `/version` readiness (15 s cap, early exit if the pid dies), probes `/proxies/<tag>/delay` against 9091 with the existing 16-way batch machinery, then tears the instance down on every exit path including `bail()`. A SIGKILL'd runner can orphan the instance; the next run reclaims it via a pidfile whose target is identity-checked against `/proc/<pid>/cmdline` containing the probe-config path, so a recycled pid is never killed by mistake. The probe config (it embeds every node credential) is 0600 and deleted at teardown. **Loop safety**: the probe config mirrors production's `route.auto_detect_interface=true` (escapes the live instance's TUN auto-route) and `default_mark=255` in tproxy(_mixed) modes (firewall.sh's OUTPUT chain skips marked sockets) — without these the probes would measure a double-hop through the live proxy. **Consequences**: (a) `include_all_nodes` deleted from UCI default/settings.js/build-config — the option is inert if it lingers in an upgraded `/etc/config/prism` (same no-migration stance as the `country_provider` removal); (b) the `_prism_test_all` selector is no longer emitted and the tag is no longer reserved (build-config `OUTBOUND_RESERVED_TAGS` + luci.prism `RESERVED_TAGS`); tag enumeration for a full run now parses the probe config itself; (c) `test_node` RPC, `probe_node` and `clash_get` are removed from luci.prism (and the ACL): the per-row Test button is now a one-tag run of the same runner, with the UI polling `test_all_status` (~5–20 s vs the old instant probe — but the old path only worked for in-config nodes at all, and unification means a node's testability no longer depends on whether some rule references it); (d) **Basic mode now prunes too**: `build_basic_outbounds` emits only `direct` + the selected members (+ `basic-auto`), dropping the old emit-everything behaviour whose stated justification was clash-API testability; (e) latency testing keeps its `clash_api_enabled` gate for UI consistency, and the live instance still emits its own clash API block on 9090 for the Status page (groups/traffic/active-watch) — only node probing moved off it. **Memory trade-off**: a second sing-box (~15–40 MB RSS) lives for the duration of a user-triggered test run; any router that runs sing-box on a 300-node config has that headroom, but this is the on-hardware verification item for the change. Verified in a stubbed harness (fake uci/jsonc/sing-box/uclient-fetch): probe build (advanced+basic fixtures), full enumeration incl. WireGuard endpoints, tag-file runs, bail path, stale-instance reclaim, and production/basic lean builds.

# Mode naming: basic / advanced, not basic / expert

Initially shipped on-branch as "basic vs expert" because the Settings tab already had an in-tab "Show advanced settings" reveal — using "Advanced" as the mode name would have collided ("the Advanced settings of Advanced mode"). With Basic mode absorbing the on-ramp audience, the in-Settings reveal was relabelled "Show all fields" (still useful — there are 12 fields + 2 whole sections + the extra.json editor behind it, more than we'd want to flatten by default). That freed the word "Advanced", which pairs more naturally with "Basic" and reads less gatekeepy than "Expert". Rename is mechanical: UCI value, `set_mode` validation, build-config gate, JS string comparisons, UI labels, code comments. Unreleased branch so no migration shim; the unknown-value fallback in `read_mode` / `get_status` is "advanced", which auto-coerces any lingering `mode=expert` from earlier snapshot installs into the new default.

# Status page gains a Start button when sing-box is stopped

The 2026-05-22 layout reasoned that "Restart on a stopped service just starts it, so no separate Start button — Stop and Restart cover every transition." That premise is wrong: the `restart` RPC at `root/usr/libexec/rpcd/luci.prism` only execs `/etc/init.d/prism restart`, while `enabled=1` is only set by the separate `start` RPC. Combined with `start_service`'s `[ "$enabled" = "1" ] || return 1` gate (the single-source-of-truth rule from *Service start path rebuilt on homeproxy's model*), Restart on a stopped+disabled instance is a no-op. On a fresh install `/etc/config/prism` ships `option enabled '0'`, so a new user had no in-UI path to bring Prism up — the violation of the UI ↔ UCI parity invariant that motivated the entry above. Fix: `status.js` adds a `callStart` RPC binding to the already-implemented `start` method (which flips `enabled=1` and execs `start`), a `handleStart` handler, and renders the action buttons dynamically — Start alone when stopped, Stop + Restart when running. The button container is regenerated by `_updateStatus` on every poll tick so the toolbar follows state changes (poll noticing a crash, a successful Stop, etc.) without needing a separate re-render path. The stale comment block above the status row is updated to describe the new three-state toolbar.

# Subscription `node_count`/`status` reconciled against the actual nodes file at every boot; `/etc/prism/nodes/` registered with sysupgrade

User report: after reinstalling OpenWrt, the subscription list still showed the old node counts and "ok" status, but no servers were actually usable. Root cause is a split similar to decision #24's cfgXXXX rotation bug but on the backup side rather than the parse side: `node_count`/`status`/`last_sync` are plain UCI options on the `subscription` section (`sync_one`, `luci.prism`), persisted in `/etc/config/prism` — a declared conffile, so a `sysupgrade` "keep settings" reinstall restores it verbatim. The actual node list is a separate file, `/etc/prism/nodes/<uid>.json`, which is **not** a conffile (conffiles compare a shipped file's checksum, and these per-subscription files are never shipped — they're pure runtime output) and was never registered anywhere for sysupgrade preservation either. Result: the UCI section survives with its old counts, the nodes file does not, `read_nodes_file` returns `{}`, and `build-config` silently emits zero outbounds for that subscription while the Nodes/Basic grid keeps showing the stale number — an honest-looking subscription with nothing behind it. Two-part fix, not mutually exclusive: (1) postinst (both the Makefile's `Package/luci-app-prism/postinst` and `package.sh`'s hardcoded duplicate — the standalone builder doesn't parse postinst out of the Makefile the way it does conffiles/deps/version) appends `/etc/prism/nodes/` to `/etc/sysupgrade.conf` if not already present, so a future keep-settings reinstall actually restores the real node data. (2) A new `reconcile_subscriptions` rpcd method walks every `subscription` section and zeroes `node_count`/sets `status=stale` when `node_count > 0` but `nodes_file(uid)` doesn't exist on disk — covering routers that reinstall without sysupgrade's keep-settings path, or upgrade from before fix (1) shipped. Called from `/etc/init.d/prism`'s `start_service`, before the `enabled` gate, so it runs on every boot regardless of whether the service ends up starting — the Nodes tab is truthful the moment the user opens it, without waiting for a manual re-sync. Uses `c:commit("prism")` via the Lua libuci binding (same as `sync_one`'s existing per-sync commits), not the ubus `uci` object, so it does not fire procd's `config.change` reload trigger — no risk of a boot-time reload loop. Registered in the ACL `write` list alongside `reload_if_changed`, another root-shell-only internal method kept there for consistency even though the browser never calls it directly.

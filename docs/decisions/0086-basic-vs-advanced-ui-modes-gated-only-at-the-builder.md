# Basic vs Advanced UI modes, gated only at the builder

`prism.global.mode` is `basic` or `advanced` (default `basic` on fresh installs, fallback `advanced` when unset so today's configs upgrade non-destructively). The flag decides which tabs the host view renders (Status + Basic, or Status + Nodes + Routing + Settings) and which UCI sections `build-config` reads. Manual nodes (`prism.node`), custom rules (`prism.rule`) and `/etc/prism/extra.json` are *kept on disk* in Basic mode; the builder simply ignores them. That makes the switch fully non-destructive in both directions — Advanced→Basic→Advanced restores everything. Basic synthesises its config from `prism.basic.{server,routing,bypass_country,ports}` + subscriptions: N=1 selected → that node is the final outbound, N>1 → a urltest tagged `basic-auto` (displayed as "Auto" on Status); country bypass emits sagernet `geoip-<cc>` + `geosite-<cc>` rule-sets matched into one OR-ed direct rule; common-ports is a fixed list of 16 ports (SSH/mail/DNS/web/DoT/IMAP/POP3/XMPP-fallback/alt-web) emitted as a single `port` matcher. Basic also forces `firewall.sh` to drop the OUTPUT-chain rules (router-originated traffic stays untunneled) regardless of the saved `inbounds.tproxy_self` value, and hides the "Subscriptions/Active rules" + sing-box-version footer rows on Status. DNS leak edge case noted in code: with fakeip off, bypassed-country domain lookups still exit via `remote` because `prepare_rules` returns `{}` and no per-rule DNS mirrors are synthesised — the resolution is over DoT so content is encrypted, classed as wart not leak. Toggle lives in two places (right-aligned chip in the tab bar + a friendlier link at the bottom of the Basic panel) per the design discussion; Advanced→Basic is gated by a one-step modal so the change is never silent, Basic→Advanced flips silently.

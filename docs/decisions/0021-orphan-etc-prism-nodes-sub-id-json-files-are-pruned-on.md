# Orphan `/etc/prism/nodes/<sub_id>.json` files are pruned on every sync, and skipped on read

`luci.prism` had no path that removed a node file when its UCI subscription section was deleted (`form.GridSection`'s standard Remove writes UCI directly with no RPC hook). A deleted-then-recreated subscription, or a manual UCI edit that changed a section id, left a file on disk whose sub_id no longer matched any UCI section — `list_all_nodes` still loaded it, surfaced its tags in every outbound dropdown (Routing's Server picker, Default-server, urltest member multi-select), and the labelling fell back to bare-tag because `subName[ob.subscription]` was undefined — making the orphan's tags look like manual nodes and, worse, collide with valid subscription tags that share names. A new `valid_sub_ids()` helper enumerates current UCI `subscription` sections; `list_all_nodes` consults it and skips files whose sub_id isn't in the set (pure read, no delete here — surprising side-effects in a read path). The actual disk delete lives in `prune_orphan_nodes()`, called at the end of `sync_subscription` and `sync_all_subscriptions` so a user-triggered sync or the hourly cron also clears the file — bounding the on-disk lag to one cron tick. Not all-encompassing: it does **not** detect a *stale-content* file (subscription still exists in UCI but its file holds content written from a previously-configured URL — Prism has no record of past URLs, and a successful sync overwrites the file anyway). That case is operator-resolved (re-sync the subscription, or remove and re-add it).

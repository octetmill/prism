# Managed-DNS drop-in uses `no-resolv` — sing-box is dnsmasq's only upstream, no ISP fallback

The earlier drop-in kept the WAN/ISP resolvers and relied on `strict-order` to "query sing-box first, fall through only when it does not answer." In practice `strict-order` did not keep `127.0.0.1#5335` ahead of the resolv-file servers: with sing-box up and resolving correctly, dnsmasq still answered LAN clients from the ISP resolver. On a censored network that resolver returns DNS-poisoned answers (e.g. `www.google.com` → a bogus IP), so managed DNS silently handed clients corrupt records while sing-box's own resolver — verified via `dig @127.0.0.1 -p 5335` — was returning correct ones. The drop-in now sets `no-resolv`, making `server=127.0.0.1#5335` dnsmasq's sole upstream: every query goes through sing-box, and the ISP servers can never be consulted. The previous "soft fallback" is dropped deliberately — a poisoned answer is worse than none, and the drop-in only exists while sing-box is meant to be running (a clean stop removes it via `remove_dns_dropin`; a crash is covered by procd `respawn`).

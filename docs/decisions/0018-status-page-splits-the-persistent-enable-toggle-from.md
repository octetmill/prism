# Status page splits the persistent Enable toggle from transient Stop/Restart; pause lives on a tmpfs marker

The previous model (homeproxy-style, decision #46) collapsed "autostart at boot" and "is it running right now" onto the single UCI `enabled` flag, with Stop/Start flipping it as a side effect. That conflated two genuinely different user intents: (a) "install Prism but keep it dormant — I'll turn it on later" (a persistent configuration choice) and (b) "stop sing-box for a minute to confirm an issue isn't its fault" (a transient diagnostic action). The collapsed model also surfaced a first-install dead-end — the Status page showed only Stop + Restart, but `restart` did not flip `enabled` back to 1, so a freshly-installed Prism (default `enabled=0`) could not be started from the browser at all. New model: two independent controls on the Status page. (1) **Enable toggle** at the top — a checkbox writing UCI `global.enabled` via a new `set_enabled(enabled)` RPC. Off = installed-but-dormant: `start_service` early-returns, watchdog exits, the runtime row is hidden entirely (`display:none`, contents still rendered so polling and re-enable don't need a full re-render). (2) **Stop / Start / Restart** as runtime-only buttons that never touch `enabled`. Stop writes a tmpfs pause marker (`/var/run/prism.paused`) before invoking `/etc/init.d/prism stop`; `start_service` and the cron watchdog both honour the marker and refuse to start a paused service. Tmpfs is the natural reset — a reboot clears the marker, so an enabled-but-paused service resumes automatically and a user who forgets to click Start after testing isn't permanently broken. Start and Restart both remove the marker before execing (otherwise `start_service` would refuse). Three runtime states show distinct badges + button sets: **Running** (`● Running` + Stop + Restart), **Paused** (`○ Paused` + Start + Restart + "Will resume on next reboot" note), **Stopped** (`● Stopped` red + Start + Restart — typically a crash that exhausted procd's respawn cap before the */5 watchdog re-armed). `get_status` returns the new `paused` field so the frontend can distinguish paused from crashed. The Autostart read-out is dropped from the footer (the Enable toggle is now its visible control). ACL gains `set_enabled` on the write list. Partially reverses decision #46: that decision was right to make `enabled` the boot gate, but wrong to make Stop write it; this re-splits the runtime concern off `enabled` without re-introducing the persistent manual/autostart flag pair the old `manual` field was. Supersedes the just-shipped *Status page gains a Start button when sing-box is stopped* (the Start button is still there, but its semantics are now "resume from pause / recover from crash", not "set enabled=1").

# `tls.utls` is stripped from QUIC-transported outbounds (`hysteria2`, `tuic`) in both the subscription sanitiser and the manual-node builder; the uTLS fingerprint picker is hidden for those types

Field report: `outbound/urltest[V1 Singapore]: unsupported usage for uTLS` on every dial, repeating in the log. Root cause is a hard incompatibility in sing-box, not a provider quirk: QUIC-carried protocols hand their TLS off to `sing-quic`, which needs a real `*crypto/tls.Config` and obtains it by calling `Config.STDConfig()` (`quic.go`'s `Dial`/`DialEarly`/`CreateTransport` all do). `UTLSClientConfig.STDConfig()` in `common/tls/utls_client.go` unconditionally returns `E.New("unsupported usage for uTLS")` — uTLS rewrites the ClientHello at the record layer, which has no meaning inside QUIC's own crypto frames — so a hysteria2/tuic outbound carrying a `tls.utls` block fails **every** connection attempt. Prism was generating exactly that from two directions: `SUB_TLS_KEYS` whitelists `utls` and copies it verbatim out of subscription payloads (and providers really do ship it — the reporting router's subscription set `utls: {enabled, fingerprint: chrome}` on all 35 of its hysteria2 nodes), and `build_tls_from_uci` emitted it for any node with `tls_fingerprint` set, while `nodes.js` offered the fingerprint picker for hysteria2/tuic in the first place. The damage is disproportionate to the config error because these nodes land in regex-matched urltest groups: on the reporting router 26 of 57 outbounds were dead, taking out 14 of 28 members of `V1 Singapore` and 12 of 24 of `V1 Taiwan` — the latter being `routing.final_outbound`, so it degraded all traffic, not just one group. Verified on the reporting hardware (OpenWrt 25.12.5, sing-box 1.13.18 `with_utls`) with ephemeral single-outbound probe instances rather than by reasoning: the unmodified node reproduces the exact log line, and the same node with only `utls` removed returns HTTP 204 in 1.8 s; three further hysteria2 nodes across both regions likewise went from dead to 204 in <2 s. **Only `utls` is filtered.** REALITY refuses `STDConfig()` identically (`"unsupported usage for reality"`), but dropping its block cannot resurrect a QUIC+REALITY node — the server expects the REALITY handshake — so that distinct error is left intact as a diagnostic rather than traded for an opaque TLS failure. ECH is explicitly *not* filtered: `ECHClientConfig` embeds `ECHCapableConfig`, so `STDConfig()` is promoted from the underlying std config and still returns a usable one. Enforcement lives in `build-config` (both the subscription and manual-node paths) rather than in `luci.prism`'s parsers, matching the existing "sanitise at emission, not at parse" split that `SUB_TLS_KEYS` already embodies — which also means the fix applies to node files already on disk with no re-sync needed. The `nodes.js` change is cosmetic follow-through: the picker offered a setting that build-config now discards, so it is no longer shown for hysteria2/tuic (`oSni`/`oInsec` keep the full forced-TLS list). Confirmed against the reporting router's real data by diffing stock vs. patched `--preview` output: 57 outbound tags unchanged, exactly 26 outbounds differ, each solely by the removal of `utls`, the 28 non-QUIC nodes keep their `utls` untouched, every non-outbound section is byte-identical, and `sing-box check` validates the result.

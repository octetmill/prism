# Subscription node files keyed by a stable `uid`, not the anonymous cfgXXXX section name

Subscription sections in `/etc/config/prism` are anonymous, and libuci does not persist anonymous section names to disk — `config subscription` is written without a name, and the `cfgXXXX` id is re-derived from a package-wide section counter (`cfg<2-hex-index><4-hex-hash-of-type>`) on every parse. The hash component depends on the section type alone, so two subscriptions only differ in the index byte, which means **anything that shifts the position of subscription sections within the file rotates every subscription's cfgXXXX id** — deleting a manual node that sat ahead of the block, dragging a node across the block in a GridSection sortable, hand-editing UCI from the CLI. After a rotation, each row's UCI-stored fields (`name`, `node_count`, `last_sync`, `url`) stay with the row (they're per-section content), but `/etc/prism/nodes/<old_cfgXXXX>.json` belongs to whichever row now happens to hold that cfg id — observed symptom is "subscription 1's servers show up under sub 2, sub 2's under sub 3" with the displayed Nodes count still matching the row's last sync. `urltest_regex_sources` stored cfgXXXX section names too, so a regex group's source allowlist was equally rotation-fragile. Fix: every subscription section carries a `uid` UCI option (16 hex chars from `/dev/urandom` / `getRandomValues`), and every cross-session reference to "which subscription" uses uid instead of section name. Files become `/etc/prism/nodes/<uid>.json`; `build-config`'s `_source` field on imported nodes is the uid; `list_outbounds` emits `n.subscription = uid`; the JS `subName` / `subOrder` maps in `nodes.js`, `routing.js`, `status.js`, `basic.js` are keyed by uid; the `urltest_regex_sources` dropdown stores uids. The section name stays anonymous (the UI remains unchanged — `s.anonymous = true`), and stays volatile — it is just no longer load-bearing. Three places allocate a uid: the GridSection `handleAdd` overrides in `nodes.js` and `basic.js` (synchronous `uci.set` on the freshly-added section, before the modal opens, so the uid is staged in the same panel save as the row itself); `sync_one` in `luci.prism` as a defensive backstop for hand-rolled sections via `ensure_sub_uid`; and the install-time `92-prism-migrate-subscription-uid` uci-defaults script, which assigns a uid to every pre-uid section, renames matching `<cfgXXXX>.json` → `<uid>.json` in lockstep, and rewrites `node.*.urltest_regex_sources` entries that referenced the old cfgXXXX. Migration assumes current state is *aligned* (cfg ids match files on disk): a router that has already rotated without re-syncing will have its uid assigned fine but the orphan files dropped on the next sync — the user re-syncs and everything repopulates under the new uid, which was already the only recovery path before. Three things deliberately kept simple: (a) one uid per section, no rotation/rekey ever (collision space is 2⁶⁴, fine for a per-router list of ≤ a few subscriptions); (b) the migration runs once and is removed by uci-defaults — subsequent installs find every section already has a uid and no-op; (c) the JS-side uid generator is inlined in both `nodes.js` and `basic.js` rather than promoted to `lib/` — eight lines × two callers is below the threshold for a shared module.

# Node latency probes via sing-box's clash API, with a fire-and-forget background runner for "Test all"

**Shipped (replaces an earlier *Planned:* entry that anticipated a different architecture — the implementation diverged several times on real hardware).** Two UCI flags gate the feature, both default off and surfaced under Settings → Latency testing (Advanced): `clash_api_enabled` controls whether `build-config` emits `experimental.clash_api`; `include_all_nodes` controls whether step 4's reference filter in `build_outbounds` lets every concrete-endpoint node into the running config (without it, only nodes referenced by a rule or group reach sing-box and the rest can't be probed). When `clash_api_enabled=1`, `build_outbounds` also emits a hidden `_prism_test_all` selector group whose members are every concrete node it wrote out — that's the handle the runner uses to enumerate testable tags. **No `secret`** on the clash API block: sing-box's auth middleware is a no-op when `secret` is absent, the API is bound to `127.0.0.1` only, and any process that can reach the port already has root on the router and can do anything via UCI / init.d directly — the secret was defense-in-depth theatre, and it would have forced the use of an `Authorization: Bearer` header that `uclient-fetch` has no flag for (sing-box only honours the `?token=` query parameter on WebSocket upgrades). `luci.prism` gains four RPCs: `test_node {tag, url?, timeout_ms?}` (single per-row probe via `clash_get` → `uclient-fetch` → `/proxies/<tag>/delay`); `test_all_start {tags?}` (fork the background runner); `test_all_status` (read the runner's status file); `get_last_latency` (read the tmpfs cache at `/var/etc/prism/latency.json`). ACL: the first three on `write`, the last on `read`. **The runner is the load-bearing piece.** `/usr/libexec/prism/test-all-runner` is a Lua script forked detached from rpcd; it reads an optional tag list from `/var/etc/prism/.test-all-tags` (the UI's per-subscription button writes the subscription's tags; the global Test-all leaves the file absent and the runner falls back to fetching `/proxies/_prism_test_all` for the full membership), pre-encodes one URL per tag (URL-encoding happens in Lua because shell-side encoding of emoji-laden CJK tags like `🇭🇰 HK1` is fragile), then shells out batch by batch — 16 backgrounded `uclient-fetch` processes per batch via shell `&` followed by `wait $PIDS`. **Subtle correctness fix discovered the hard way:** `awk \| while ... done` puts the while loop in a subshell, so `PIDS` would vanish on the subshell's exit and `wait` would join nothing — leaving probes orphaned. The runner instead `sed -n`'s the batch into a side file and reads with input redirection, so the loop runs in the current shell and `wait` actually waits. After each batch the per-tag result files are parsed and merged into `latency.json` atomically, and `.test-all-status` is updated with `{ running, started_at, total, done, ... }` — the UI polls `test_all_status` every 1.5 s and refreshes cells from `get_last_latency` between ticks, so results appear progressively. **Why fire-and-forget at all:** the original plan was a synchronous `test_group_delay` RPC that called `clash`'s own `/group/<tag>/delay` endpoint. On real hardware that endpoint takes ~50 s for ~300 nodes (sing-box's internal probe pool concurrency is much lower than the documented 10), and LuCI's XHR layer hard-aborts at `L.env.rpctimeout` (default 20 s, reset by rpc.js's `Request.post` from a microtask — bumping it synchronously around the call doesn't survive the dispatch). Two attempts to plumb that through both failed; the background-runner pattern removes the long-running-RPC shape mismatch entirely. The earlier 50 s wall-clock then improved further: per-tag probes via uclient-fetch let us pick our own concurrency (16) above sing-box's internal cap, dropping a 303-node batch from 4 m 20 s (group-delay path, ~99 unreachable nodes holding internal slots) to 41 s. UI: Nodes panel's manual `form.GridSection` grows a `Latency` `form.DummyValue` column (returns a coloured `label-*` span via `formatLatency`) and a `Test` `form.Button` (per-row probe via `test_node`). The Subscriptions section's Add row also carries a section-header `Test all` button (next to `Sync all now`) so it's visible without scrolling past the node list; the Subscription View modal grows the same Latency column plus `Test all in this subscription` (writes the sub's tags to the runner's tag-file). Cells are tracked through a `tag → [<span>]` map (`_registerLatencyCell` / `_refreshLatencyCell`) rather than a CSS attribute selector — `querySelectorAll` for an attribute value containing surrogate-pair emoji throws SyntaxError in some browsers, breaking the whole batch promise. Subscription modal is widened to `min(80vw, 850px)` by mutating `.modal`'s `max-width` after `ui.showModal` renders (the inner content's `min-width` overflowed LuCI's stock `.modal` max-width and the underlying GridSection bled through on the right). The active-member dropdown on Status, the by-latency table sort, the post-sync `[Test now]` link, and the periodic auto-test timer are all deferred. **Trade-off:** with `include_all_nodes=1` a 300-node subscription emits ~175 KB more JSON into `/var/etc/prism/sing-box.json` and ~600 KB of Go state into sing-box (each idle outbound is ~1–2 KB) — fine on any router that runs sing-box at all, but worth knowing about.

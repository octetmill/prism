# Subscription URI parser: the authority ends at the first `/` — `split_host_port` strips any path; base64 detection no longer falls through to `unknown`

Field report: an SSRDog subscription synced `format=unknown, 0 node(s)` and the user reasonably blamed the per-subscription User-Agent option ("works from my computer"). The UA was a red herring — `uclient-fetch -U` sends it correctly (verified in uclient source: custom headers live in `uh->headers`, which redirects do not clear) and the fetch succeeded. The real bug: the provider returns base64-encoded `anytls://…@host:port/?insecure=1&…` URIs, and `parse_proxy_uri` splits the authority from the query at `?` only, so the host:port handed to `split_host_port` keeps the path's trailing `/` and the `^(.+):(%d+)$` port match fails — every node in the sub was rejected, the base64 branch's `#nodes > 0` gate then fell through, and the body was mislabelled `unknown`. The `/?query` shape is emitted by common generators (Shadowrocket-style `ss://` links too), not an SSRDog quirk. Fix in `split_host_port` itself — both its callers (the `ss://` branch and the generic userinfo@host:port branch) pass URI authorities, where a path is meaningless for every supported scheme (transport paths arrive via the `path=` query param), so stripping from the first `/` fixes all schemes in one place and cannot affect bracketed-IPv6 matching (`]` precedes the port, never a `/`). Companion: the base64 branch now returns `format=base64` even with 0 nodes — a plain URI list can never pass the base64-alphabet check (every URI contains `:`, which is outside the alphabet), so the fall-through could only ever relabel a genuine base64 parse failure as `unknown`, hiding the format from the sync log that is the main diagnostic for exactly this class of bug. Verified by extracting the real parser block into a Lua 5.1 harness: SSRDog-shaped anytls plus trojan/hysteria2/ss/vless-with-IPv6 URIs all carrying `/?` paths parse to correct host/port, pathless URIs unchanged, garbage base64 reports `base64, 0 nodes`.

# Section identity in `/etc/config/prism` IS the section name (16-hex uid), for every anonymous section type — supersedes the parallel-`uid`-field scheme

Decision #14 fixed the rotating-cfgXXXX hazard for `subscription` by adding a `uid` UCI option alongside the still-anonymous section, then keying files / cross-references on the field instead of `s[".name"]`. The fix worked, but left two footguns: (a) `cfgXXXX` is still minted and is structurally identical to a "real" id — nothing structurally stops a future patch from grabbing `section.section` again, and the rule against it was convention-only; (b) the same rotation hazard existed for every other anonymous type, most acutely for `rule` ↔ `condition`, where `condition.rule = <rule's cfgXXXX>` is rotation-fragile in exactly the way subscription files were (deleting one rule shifts every other rule's cfgXXXX, the conditions then point at stale ids and either orphan or attach to the wrong rule). Decision: make every anonymous prism section a NAMED section whose name is a 16-hex random uid generated at create time. The section name IS the id; libuci persists it; `cfgXXXX` is never generated for prism sections anymore. Affects `subscription`, `rule`, `node`, `condition`, `customrs`, `bypass`. No `uid` UCI field on any of them — `s[".name"]` everywhere. UI label-hiding is unchanged (`s.anonymous = true` on `form.GridSection` is a display flag and works identically on named sections). One shared JS module `view.prism.uid.generate()` (16 hex from `crypto.getRandomValues`, `Math.random` fallback) is required from `nodes.js` / `basic.js` / `routing.js` and called from every `handleAdd` override + the condition allocator (`routing.js parse()`'s `uci.add('prism', 'condition', uid.generate())`); the inlined `generateSubUid` duplications from #14 are removed. The Lua rpcd handler drops `ensure_sub_uid` and replaces it with `stabilise_section_name` — a `c:rename` backstop that promotes any post-install hand-rolled `^cfg` section (e.g. someone running `uci add prism subscription` over SSH) to a stable uid on the first `sync_one`. The install-time migration `93-prism-migrate-named-sections` (replacing 92) handles the schema flip in a single uci-defaults pass: (1) collect every `^cfg`-named section across the 6 affected types; (2) for `subscription`, adopt any existing `uid` field from a 92-already-run router as the new section name so file paths and `urltest_regex_sources` entries already rewritten by 92 stay valid without further work; (3) rewrite `condition.rule` values from old cfg → new uid, using a captured rule-rename map, BEFORE any rename so the stored value still matches; (4) rewrite `node.urltest_regex_sources` entries the same way (subscription-rename map); (5) rename `/etc/prism/nodes/<old>.json → <new>.json` for subscriptions only (no-op on 92-migrated routers — file is already at `<uid>.json`); (6) drop the now-redundant `subscription.<sid>.uid` field; (7) `uci rename` every section; (8) single `uci commit prism`. Idempotent (uid-shaped names are skipped) and safe to re-run. Trade-offs called out: `condition` sections get a uid name even though they're churn-heavy (recreated on every rule modal save) — uniformity wins, and burning a handful of uids from 2⁶⁴ on every rule save is a non-concern; raw `/etc/config/prism` reads less prettily over SSH (every section now has a hex name), but `option name` carries the human label anyway. The previous decision #14 is the stepping stone this builds on — its migration covered subscription files in production, and 93 adopts whatever uid 92 already assigned. Replaces #14 as the canonical reference.

# Clash YAML `proxies:` parser: entry dashes may sit at any indentation, including flush with `proxies:` itself; block-style array values (e.g. `alpn:` / `- h2` / `- http/1.1`) no longer fragment the entry

Field report: a subscription with 36 valid `anytls`/`hysteria2` proxies synced to `0 node(s)` — "no usable server". Root cause in `extract_clash`: the line-loop treated any line starting with a non-whitespace character as the end of the `proxies:` list, but the provider's YAML wrote entries as `- name: ...` at column 0 (flush with `proxies:`, not indented under it) — equally valid YAML to the more common `  - name: ...` style, and apparently common among Clash Meta subscription generators. Since `-` is non-whitespace, the very first entry line tripped the termination check and `in_proxies` went false before a single proxy was read. Fix: only treat a leading-non-whitespace line as list-end when it is *not* a dash; a dash line starts a new entry regardless of its indentation. That surfaced a second, previously-latent bug in the same loop: any indented dash line (e.g. a block-style `alpn:` array's `- h2` / `- http/1.1` sub-items) was *also* read as a new-entry dash, silently truncating the current entry's remaining fields once such an array appeared — harmless by luck for fields defaulting the same as their absence (`skip-cert-verify: false`), but `alpn` was dropped outright. Fixed by recording the indentation of the first entry dash (`entry_indent`) and treating any *deeper*-indented dash as a nested list item — appended into a pending list field (opened by a `key:` line with an empty value) and closed into the bracket-string shape `clash_parse_list` already expects, rather than flushed as a new entry. This is exactly the sibling-sequence-items-share-one-indentation invariant YAML itself guarantees, so the heuristic cannot misfire on valid input. Verified by extracting the real parser block into a Lua 5.1 harness: the reported subscription now yields all 36 nodes with `alpn` populated; a synthetic indented-block fixture (2-space entries, nested `alpn:` list) and an inline-flow fixture both still parse correctly and still stop cleanly at `proxy-groups:`.

# Status gains an inline default-node switcher (Advanced mode), a first-run Get-started checklist, and cross-tab staged-change indicators

The switcher edits `routing.final_outbound` through the standard staged-save + plain-apply path (`uci.save()` → `ui.changes.apply()`, same as `formpanel.saveApply`), so the procd UCI trigger reloads sing-box and the page-reload-plus-session-store flow lands back on Status showing the new node — no bespoke apply machinery. It applies immediately because Status is the immediate-action surface (Enable, Stop/Start/Restart all act on click) and a default-node change is only useful once applied; but since apply commits the *whole* staged set, a confirm modal discloses any changes staged by earlier edits before they ride along. Clash-API group-member forcing was deliberately left out: sing-box urltest groups select members by latency, and forcing a member needs verification on real hardware first. Basic mode keeps the read-only text — its server picker is a multi-select on the Basic tab and the synthesised `basic-auto` tag is not something to rebind from Status. The choice list is shared with Routing's dropdowns via `subs.serverEntries` so the two cannot diverge. Companion visibility work in the host: tabs that staged changes get a dot in the tab bar (growth in `uci.changes()` between tab activations is attributed to the tab being left) and the footer notes the staged count next to Save & Apply — the per-tab footers otherwise imply a per-tab commit scope that doesn't exist, since every panel shares one UCI config.

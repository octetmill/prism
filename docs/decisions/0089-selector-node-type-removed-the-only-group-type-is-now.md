# Selector node type removed; the only group type is now `urltest`

Decision #28 added the `selector` node type as a manual-pick group sharing `urltest_outbounds` plus a `selector_default` field. In practice it was half-implemented: the editor stored `selector_default` but Prism shipped no runtime switcher (the deferred Status dropdown from decisions #17 / #27 never landed), so a selector group behaved as a static pin to one node — a job a routing rule pointing directly at the node, or the Default-server picker, already does without the extra indirection. urltest stays useful because auto-rotation by latency isn't replicable any other way; selector was not earning its UI surface. Removal scope: the `selector` entry is dropped from the Type dropdown (`nodes.js`); `selector_default` and its dynamic `ui.Dropdown`-via-renderWidget plumbing (the `setTimeout(0)` clone-map lookup pattern from decision #28) are gone; the modal tab reverts from "Group" to "URLTest"; basic.js / status.js / routing.js comments drop their selector references and the Status _renderGroupMeta selector branch is removed. `build-config`'s `build_node_from_uci` no longer builds a selector outbound — a legacy UCI `type=selector` section is converted in-memory to `type=urltest` (member list preserved, `selector_default` dropped) so an upgraded install with stored selectors keeps routing without breaking sing-box. Step 3's group expansion and step 4's empty-group skip both narrow back to `urltest` only. **The `_prism_test_all` hidden helper** stays a `type="selector"` outbound: it's a sing-box-level construct that holds every concrete-endpoint tag for clash-API batch probing, and selector is exactly the right sing-box type for "group that never auto-probes" — the user-facing removal is about the *node creation surface*, not sing-box's outbound type itself. `_prism_test_all` is filtered from `active-watch`'s group snapshot by the existing underscore-prefix rule plus a defensive `p.type == "URLTest"` narrowing, and from the Basic node picker by `GROUP_TYPES = { urltest: true }` (clash-format subscriptions can't smuggle selectors through anyway — `SUB_ALLOWED_TYPES` only admits concrete protocol types, so no remote selector ever reaches Prism). `luci.prism` gets a `migrate_legacy_selectors` helper invoked once per RPC `call` dispatch: it rewrites any UCI `node` section with `type=selector` to `type=urltest`, deletes the `selector_default` option, commits, and logs `migrated legacy selector node(s) to urltest`. The migration is a no-op on clean installs and fires at most once per upgraded router (after the first RPC, the UCI state is canonical and subsequent calls find nothing to migrate). The in-memory fallback in `build-config` is the safety net for the narrow window where build-config runs before any rpcd RPC has — e.g. boot path, hand-edit via SSH between an upgrade and the first UI visit. No standalone uci-defaults migration script: the dispatch-time helper covers every realistic upgrade path and avoids a one-shot pass that needs its own idempotency guard. ACL is unchanged (the migration runs as part of the existing handler, no new method). `get_active_groups` drops the `s.type == "selector"` UCI scan branch, the `entry.type == "Selector"` snapshot translation, and the `selector_default` lookup. The deferred Status-tab runtime switcher mentioned in #17 / #27 stays deferred — removing selector doesn't preclude re-adding it later if the indirection-with-runtime-flip use case proves valuable; the rebuild would be a write-path RPC (`/proxies/<tag>` PUT) plus a single `ui.Dropdown` in `_renderGroups`, not a re-introduction of the editor UI.

# UI restructured to 4 flat tabs (Status / Servers / Routing / Settings); Settings uses an Advanced expander; vocabulary swap Outbound → Server

The 2026-05-22 layout (Overview / Outbounds / Routing / Settings parent with 5 sub-tabs / Diagnostics) was researched against peer sing-box clients (Hiddify, Clash Verge Rev / Mihomo Party, Nekoray, HomeProxy, GUI.for.SingBox) and against general progressive-disclosure UX literature, and replaced. Three observations drove the change: (1) every consumer-facing client renames `outbound` — sing-box internal jargon — to a friendlier noun (Clash family uses "Proxies", Nekoray uses "Servers"); the user picked **Servers**, which is now the term in tab names, the routing rule column ("Server"), the default-fallback section ("Default server") and sync notifications. The UCI schema (`node`, `subscription`), the RPC method names (`list_outbounds`) and the on-disk sing-box JSON keep the historic spelling — wire format is unchanged, only labels move. (2) the "is it working / why not?" mental flow was split across Overview and Diagnostics for no reason; they are now one **Status** tab — service controls + the *active* default server (read from `routing.final_outbound` at render time) + a fixed 20-line log tail at 2s polling + Subscriptions/Active-rules counts + a footer (`sing-box X.Y.Z · Autostart · Mode`). The full log viewer and the generated-config preview moved into on-demand modals, off the always-visible glance. (3) the 5 Settings sub-tabs became one `form.Map` on one scroll page. Basic options (log level, network mode + IPv6, managed DNS, local/remote DNS, fake-IP) are visible by default; the Advanced fields (TProxy/Mixed ports, "proxy router traffic", TUN address/MTU/stack/auto-route, DNS strategy, Fake-IP ranges) and the raw `extra.json` editor are hidden behind a single `<details>` toggle that flips a `prism-show-advanced` class on the form root — a tiny inline `<style>` block keys row visibility off that class, so the disclosure is one DOM mutation rather than a Map rebuild. Multiple `form.NamedSection`s binding the same UCI section name would collide on the generated DOM id, so each UCI section (`global`, `inbounds`, `dns`) gets exactly one NamedSection; the Basic/Advanced split is achieved by tagging individual options at construction time (an `advance()` helper pushes the option into a list) and adding the CSS class to each one's enclosing `.cbi-value` row at post-render. depends() works unchanged because all options share the same Map. The `enabled` UCI flag is intentionally **not** in Settings: Status owns runtime control via Start/Stop, so the master flag has one source of truth — a duplicate toggle would invite a sequence where the user disables in Settings, returns to Status, and sees Stopped without remembering why. The former Rule-sets sub-tab (delivery / download detour / country provider + custom rule-sets) is folded into **Routing**, since it only exists to back a rule's `ruleset`/`country` conditions — co-location avoids the tab-hop on every new rule that needs a custom rule-set. Tab redirection: stored session ids `overview`/`diagnostics`→`status`, `outbounds`→`servers`, any `settings/<sub>`→`settings`, so a Save & Apply (which reloads the page) lands on the equivalent merged tab instead of `TABS[0]`. Deliberately deferred: an inline `ui.Dropdown` group switcher on Status — it would let the user flip the active selector member from the landing page, but it is the only piece that *writes* cross-tab state and needs a focused RPC plus dropdown plumbing; for now the active group is read-only text. The first-run wizard (Hiddify pattern: paste subscription → pick mode → enable) is also deferred.

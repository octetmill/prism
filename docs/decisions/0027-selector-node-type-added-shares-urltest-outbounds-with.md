# Selector node type added; shares `urltest_outbounds` with urltest, gets a `selector_default` field; modal tab renamed URLTest → Group

sing-box `selector` is structurally a `urltest` minus the latency probe (no `url`/`interval`/`tolerance`) plus an explicit `default` member. The member-list UCI key `urltest_outbounds` is reused for selector nodes rather than introducing a parallel `selector_outbounds` — the field is identical in shape, and a single shared `MultiValue` keeps both the form-row code and `build-config`'s prune-missing-members pass single-sourced. Selector is manual-only — regex mode would leave the default with no stable referent — so `urltest_mode` / `urltest_regex` stay urltest-exclusive; `selector_default` is selector-exclusive (a `ListValue`, optional — empty means sing-box uses the first member; the dropdown is dynamically filtered to just the section's picked `urltest_outbounds`. The widget is constructed directly as a `ui.Dropdown` inside an overridden `renderWidget` because `form.ListValue`'s default rendering uses `ui.Select` (a native `<select>`, form.js:4697) which has **no `addChoices` / `clearChoices` methods** — only `ui.Dropdown` does (form.MultiValue uses it, form.js:5236). Initial choices are seeded as `{'': '— none —'}` only; one `setTimeout(0)` later — after the modal is mounted in the DOM and the modal map's section.load chain has populated each cloned option's `.data[section_id]` — a deferred callback reads the picked tags via `pickedMembers` and calls `addChoices(picked, labels)` to fill the dropdown, then `setValue(saved)` restores the saved default if it is still a member. The deferred path is required: at the synchronous renderWidget pass during modal open, the clone's `urltest_outbounds.cfgvalue(section_id)` returns empty even though the data is set on the *outer* option — verified by re-invoking renderWidget from devtools after the modal mounts, which produces the correct dropdown. Subsequent live edits go through `urltest_outbounds.onchange` calling `clearChoices(true)` + `addChoices(...)`. **Crucial cross-map note**: `form.GridSection.renderMoreOptionsModal` (form.js:3814) builds a *separate* modal `CBIMap` with *clones* of every option via `cloneOptions` (form.js:3755). `AbstractValue.getUIElement` (form.js:1892) uses `this.map.findElement(...)` which only searches its own map's DOM. So an onchange handler that closure-captures the outer `oDefault` reaches the wrong map and gets `null` back from `getUIElement`. The handler instead resolves the sibling via `this.map.lookupOption('selector_default', section_id)` — inside the modal `this.map` is the modal's clone, so the lookup returns the modal-side clone of the option and its `getUIElement` finds the live widget. The same rule applies to `pickedMembers` reading the picked tags via `this.map.lookupOption('urltest_outbounds', section_id)`.). Step 3's group expansion is widened from `ob.type == "urltest"` to either group type so a selector's members are pulled into `referenced[]` and dangling tags pruned; the same pass also drops a stale `selector_default` whose member is no longer present. The modal tab is renamed "URLTest" → "Group" since it now covers both. `urltest` + `selector` are also moved to the top of the type dropdown — they are the two outbound-group types and the most common targets for a routing rule's `outbound`.

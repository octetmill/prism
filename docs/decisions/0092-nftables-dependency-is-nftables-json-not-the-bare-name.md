# nftables dependency is `nftables-json`, not the bare name `nftables`

The Makefile originally declared `+nftables`, but no package by that name exists on OpenWrt 24.10 / 25.12 — the userspace tool ships split into two mutually exclusive variants: `nftables-json` (the one fw4 pulls in, with JSON output for `nft -j …`) and `nftables-nojson` (the slim build without JSON). The LuCI package manager surfaced the missing name as NOT AVAILABLE in Prism's dependency tree. `firewall.sh` only uses `nft -f <file>` and `nft delete table`, so either variant satisfies it at runtime; on disk the two packages conflict because both own `/usr/sbin/nft`. Picking `nftables-json` because (a) it's the variant every default 24.10/25.12 install already has via fw4, so the dep is a no-op on stock systems, and (b) the alternative — declaring `nftables-nojson` — would refuse to install on any router that already has `nftables-json`, i.e. almost all of them. `firewall4` was considered as an umbrella dep (would also guarantee `nft` plus the kmods Prism's `inet prism` table uses), but the existing target-platform note in CLAUDE.md explicitly avoids pulling fw4 in since Prism doesn't integrate with it (no zone/include hooks), and a user who deliberately swapped fw4 out shouldn't have it forced back on. The OpenWrt SDK alternation syntax `+nftables-json||nftables-nojson` was a third option but the standalone `package.sh` builder doesn't parse alternation into apk/ipk control output, so the alternation would silently degrade to whichever side the awk extractor picks first — not worth the asymmetry. CLAUDE.md's Firewall bullet and Required-deps table updated to call out the split so future maintainers don't reintroduce the bare name.

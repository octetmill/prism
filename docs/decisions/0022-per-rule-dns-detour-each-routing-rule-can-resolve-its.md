# Per-rule DNS detour: each routing rule can resolve its domain matchers through the same outbound the connection takes

Previously `build_routing_dns_rules` mirrored every proxied rule's domains onto a single `remote` DNS server, which itself detours through `route.final` (the Default server). So a rule routing Disney to `法国 01` had its DNS resolved through whatever the user picked as Default (e.g. `V1 SouthKorea`) — geographically inconsistent with the connection, and visibly wrong for CDNs that geolocate by resolver IP (Netflix in particular). New per-rule flag `rule.dns_via_outbound` (UCI option, default `1` — unset is treated as on so existing rules upgrade transparently) makes `build_routing_dns_rules` mirror the rule onto a dedicated `remote-<outbound-tag>` DNS server whose `detour` points at the rule's own outbound. `build_dns` emits one such server per distinct flagged outbound (deduplicated, sorted for deterministic output, same upstream address as the main `remote` so the user's resolver choice carries through). Unflagged rules, `direct`-routed rules and fakeip-mode rules keep the previous mirror targets exactly. UI surfaces a Flag option under the rule modal's outbound picker; it depends-shows only when the picked outbound is a real proxy tag — `direct` resolves via `local` and `block` produces no DNS rule, so the flag is moot for both. LuCI's `depends()` has no "not equals" form, so `addServers()` now returns the proxy tag list it added and the depends loop ORs one clause per tag. Cost: one extra DNS server per distinct outbound used by flagged rules + a first-query connection bootstrap on each (negligible — those outbounds are reused for traffic anyway). Benefit: CDN region selection follows the proxy exit instead of the default outbound. Sing-box's own DNS server tag namespace is separate from the outbound namespace and accepts arbitrary strings, so `remote-V1 SouthKorea` / `remote-法国 01` work as tag names without escaping.
